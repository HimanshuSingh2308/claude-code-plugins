# Game Integration Checker Agent

You verify that a newly added game is correctly integrated into the Weekly Arcade project. Run after all other add-game agents have completed.

## Step 0: Game context

Requires a Weekly Arcade game. Load `game-context` first; if the result is standalone, stop and tell the user this only works for Weekly Arcade games.

## Required Input

GAME_SLUG, GAME_NAME, GAME_TAGS (genre tags), and the list of ACHIEVEMENT IDs.

## Checks

### 1. File Existence
- [ ] Game page exists: `apps/web-astro/src/pages/games/{GAME_SLUG}.astro`
- [ ] Game data exists (Astro): `apps/web-astro/src/data/games/{GAME_SLUG}.json`
- [ ] Game source entry exists: `apps/web-astro/game-src/{GAME_SLUG}/main.js` (new games)
- [ ] Game JS exists: `apps/web-astro/public/games/{GAME_SLUG}/game.js`, and its first line is the
      generated banner `/* GENERATED from apps/web-astro/game-src/{GAME_SLUG}/ by scripts/build-games.mjs. ...`
      (`head -1`); a missing banner means it was hand-written or hand-edited
- [ ] `node scripts/build-games.mjs --check` passes (the committed bundle matches the source)
- [ ] The page loads it with `<script is:inline src={gameAsset('{GAME_SLUG}', 'game.js')}>` and
      contains no inline game logic and no inline `onclick` handlers
- [ ] The generated `game.js` declares no top-level globals other than intentional `window.*`
      assignments (an esbuild IIFE has none by construction; a hand-edit would add them)
- [ ] Shared services are reached only through the platform adapter: `grep -rn "window\.\(gameCloud\|gameHeader\|apiClient\)" apps/web-astro/game-src/{GAME_SLUG}/`
      hits only `platform/`, and nothing in `game-src` imports from `/js/`

**Fallback mode.** If `scripts/build-games.mjs` does not exist in the checkout (the WA
modular-source PR is not merged), skip the `main.js`, banner and `--check` items, accept a
hand-written single IIFE `game.js`, and say in the report that fallback mode applied.

**Where to grep.** Every grep-based check below (`gameHeader.init`, `submitScore`, `loadState`,
`metadata:`, `addCoins`, achievement IDs) runs over `apps/web-astro/game-src/{GAME_SLUG}/**` as
well as `apps/web-astro/public/games/{GAME_SLUG}/`. Report findings against the source file and
line, since that is what gets fixed.
- [ ] Game CSS exists: `apps/web-astro/public/games/{GAME_SLUG}/styles.css` (if separate)
- [ ] SVG thumbnail (STILL) exists: `apps/web-astro/public/images/thumbnails/{GAME_SLUG}.svg`
- [ ] If `apps/web-astro/public/images/thumbnails/animated/{GAME_SLUG}.svg` exists, the
      still above is its generated output: `node scripts/thumbnail-still.js --check`
      passes and `src/data/thumbnails-animated.ts` lists the slug
- [ ] No raw `<img src="/images/thumbnails/` was introduced — thumbnails render through
      `<GameArt>`; grep the diff. Nothing outside `GameArt.astro` references
      `thumbnails/animated/`
- [ ] Score validation config exists: `apps/api/src/leaderboard/config/game-config.ts` (grep for GAME_SLUG)
- [ ] Service worker updated: `apps/web-astro/public/sw.js` (grep for GAME_SLUG paths)

### 2. gameId Consistency
Grep for the GAME_SLUG string across all relevant files. It must match exactly in:
- Game source in `game-src/{GAME_SLUG}/**` and the generated `game.js` (submitScore, loadState, gameHeader.init with `buttons: ['sound', 'leaderboard', 'auth']`)
- GAME_REGISTRY entry
- Achievement category
- Sitemap (auto-generated by @astrojs/sitemap)
- Landing page card href
- Games index page card href
- JSON-LD entries (homepage + /games/ page)

Flag any mismatches.

### 3. Landing Page (Homepage)
- [ ] Hero badge mentions GAME_NAME
- [ ] Game card exists with correct href at position 0 (top of grid)
- [ ] Only ONE game has the NEW tag
- [ ] Game counts are AUTOMATIC (verify `import.meta.glob` pattern exists in frontmatter — do NOT check hardcoded numbers)

### 4. Games Index Page (`/games/`)
- [ ] Game card exists in `/games/index.astro` with correct href at position 0 (top of grid)
- [ ] ItemList JSON-LD is AUTOMATIC (verify `itemListSchema` is generated from glob in frontmatter)
- [ ] Game counts are AUTOMATIC (verify `gameCount` variable used in template expressions)
- [ ] Only ONE game has the NEW badge

### 4b. About Page (`/about/`)
- [ ] AUTOMATIC — verify `import.meta.glob` pattern exists in frontmatter (games grid and stats auto-populate)

### 5. Category Pages
Based on GAME_TAGS, verify each matching category page:

| Genre Tag | Category Page |
|-----------|--------------|
| puzzle | `apps/web-astro/src/pages/games/puzzle/index.astro` |
| arcade | `apps/web-astro/src/pages/games/arcade/index.astro` |
| strategy | `apps/web-astro/src/pages/games/strategy/index.astro` |
| 3d | `apps/web-astro/src/pages/games/3d/index.astro` |
| action | `apps/web-astro/src/pages/games/action/index.astro` |
| brain-training / logic | `apps/web-astro/src/pages/games/brain-training/index.astro` |
| casual / relaxing | `apps/web-astro/src/pages/games/relaxing/index.astro` |
| quick / daily | `apps/web-astro/src/pages/games/quick/index.astro` |
| no-ads | `apps/web-astro/src/pages/games/no-ads/index.astro` |
| card | `apps/web-astro/src/pages/games/card/index.astro` |
| sports | `apps/web-astro/src/pages/games/sports/index.astro` |
| simulation | `apps/web-astro/src/pages/games/simulation/index.astro` |
| multiplayer | `apps/web-astro/src/pages/games/multiplayer/index.astro` |
| family | `apps/web-astro/src/pages/games/family/index.astro` |
| offline | `apps/web-astro/src/pages/games/offline/index.astro` |

**Also check `/games/popular/index.astro`** — remove `isNew` from the previous game if present (do NOT add new game unless it's curated by engagement data).

For each matching category page:
- [ ] Game exists in the `games` array in frontmatter
- [ ] Only ONE game has `isNew: true`
- [ ] Slug matches exactly

If a genre has no category page (e.g., `sports`, `simulation`), note it as info (not error).

### 6. Shared Package
- [ ] GAME_REGISTRY has entry with matching id
- [ ] All achievement IDs from the PRD are registered in achievements.ts
- [ ] GAME_SLUG exists in AchievementCategory union type

### 7. Sitemap
- [ ] Sitemap is auto-generated by @astrojs/sitemap integration — verify game page exists so it will be included

### 8. Backend Contract Validation
- [ ] Game config exists in `apps/api/src/leaderboard/config/game-config.ts` with `allowedMetadataKeys`
- [ ] All metadata keys sent by the game's `submitScore()` call are in the `allowedMetadataKeys` array
- [ ] No `addCoins()` calls anywhere in the game code (grep `game-src/{GAME_SLUG}/` and `public/games/{GAME_SLUG}/` for `addCoins`)
- [ ] All achievement IDs referenced in game code exist in `packages/shared/src/lib/constants/achievements.ts`

To verify metadata keys:
1. Grep `game-src/{GAME_SLUG}/` (and the game file) for `metadata:` to find all keys sent
2. Read game-config.ts entry for the game's `allowedMetadataKeys`
3. Confirm every sent key is in the allowlist (plus common keys: `perfectGame`, `streakBonus`)

### 9. Build Verification
Run:
```bash
node scripts/build-games.mjs --check   # skip in fallback mode
npx nx run shared:build
npx nx run api:build
npx nx run web-astro:build
```
Report any build errors. Include API build to catch game-config.ts issues. After the web build,
`git status` must show no change to `public/games/{GAME_SLUG}/game.js`; a diff means the
committed bundle was stale.

- [x] Homepage — OK (card at position 0 + hero + dynamic counts via glob)
